# Lantell — marketing site

The public site at **lantell.io**. Next.js 16 (App Router) + React 19 + Tailwind **v3**, deployed by
the Vercel project `lantell-landing`. The product itself lives in a separate repo and is served from
`app.lantell.io`.

Until this replaces it, `main` held a single static `index.html` "Coming Soon" page with a waitlist
form. That page is in this repo's history if it is ever needed again.

## Branches

| Branch | What Vercel does with it |
|---|---|
| `main` | **Production.** A push here deploys to lantell.io and www.lantell.io. |
| `staging` (and any other branch) | **Preview.** Gets its own URL, behind Vercel's login. Nothing public changes. |

`vercel.json` pins the framework preset to `nextjs`, so a branch builds correctly regardless of the
project's dashboard setting.

## Running it locally

```bash
npm install
npm run dev        # http://localhost:3001
npx tsc --noEmit   # the verification step
npm run build      # don't run while `npm run dev` is live — it corrupts the shared .next
```

Port 3001 is deliberate: the app repo's dev server owns 3000, so both can run at once.

## Environment variables

Local values go in `.env.local` (gitignored); hosted values go on the Vercel project. `.env.example`
documents each one. Everything degrades gracefully when a variable is missing — nothing throws.

| Variable | Scope | Without it |
|---|---|---|
| `NEXT_PUBLIC_POSTHOG_KEY` | Production only | Analytics is a complete no-op: no init, no network. |
| `NEXT_PUBLIC_SITE_URL` | optional | Falls back to `https://lantell.io` for metadata, robots and the sitemap. |
| `DEMO_REQUEST_ENDPOINT` | Production + Preview | The demo form accepts the submission and discards it. |
| `DEMO_REQUEST_SECRET` | Production + Preview | Same — and it must match the value on the app project. |

## How the demo form works

The browser posts to this site's own `/api/demo-request`, which checks a honeypot field, rate-limits
by IP, validates the address, and forwards it to the **app's** `/api/demo-request` with a shared
secret. The app — which already holds the database service-role key for its own reasons — writes the
`demo_requests` row and sends the notification email. This site never holds a database key.

## Notes for anyone editing the design

- **Tailwind v3, not v4.** v4-only syntax breaks the Turbopack build.
- Fonts come from `next/font` (self-hosted at build time). The static `.ttf` cuts in `public/fonts/`
  exist for the Open Graph image, which is generated by Satori and cannot use CSS.
- No `-webkit-font-smoothing` anywhere: the reference design didn't have it, and adding it changes
  every weight on the page.
- Border radius is 0 everywhere. That is a design decision, not an oversight.
- Anything unknown in `/privacy` or `/terms` is written `[[like this]]` and renders as a visible
  marker. A page that still has one also passes `draft` to `LegalPage`, which adds a "not yet in
  force" notice — drop the prop once the gaps are filled, because a published policy that announces
  it isn't in force is worse than none.
